# ADR の作成 (zero-second)

## Step 1: 既存の ADR を確認する

- `docs/adr/README.md` の一覧を読み、同じテーマの ADR がないか確認する
- ある場合は、書き換えずに新しい ADR を作り、古い方のステータスを `廃止（NNNN で置き換え）` にする

## Step 2: 番号とファイル名を決める

- 番号は一覧の最大 + 1（4 桁、欠番にしない）
- ファイル名は `NNNN-英語の短い名前.md`（例: `0012-notification-channel.md`）

## Step 3: 本文を書く

`docs/adr/template.md` の見出しをそのまま使う。

- **タイトル**: 決めたことを短く（「〜にする」「〜を使う」）
- **背景**: 何に困っていて、どんな制約があったか。会話や issue で出た前提を具体的に
- **決定**: 読んだ人がそのまま従えるように具体的に（ファイル名・設定値・コマンドを含めてよい）
- **理由**: なぜその案にしたか
- **検討した他の案**: 選ばなかった案と、その理由を最低 1 つ
- **影響**: 良くなること・悪くなること・今後気をつけること
- ステータスは `提案`、日付は今日（YYYY-MM-DD）、関連する issue / ADR を書く

推測で埋めない。背景や理由がユーザーとの会話から読み取れない場合は確認する。

## Step 4: 一覧と関連ドキュメントを更新する

- `docs/adr/README.md` の一覧に追記する
- 判断がコーディングルールや手順に関わるなら、`docs/development/coding-guidelines.md` や `CLAUDE.md` から ADR へリンクする

## Step 5: PR

ADR だけの変更なら `docs/<内容>` ブランチで PR を出す。合意できたらステータスを `採用` にしてマージする。
