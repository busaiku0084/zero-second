# 0001. 設計判断を ADR で記録する

- ステータス: 採用
- 日付: 2026-10-09

## 背景

個人開発で、AI（Claude Code）と一緒に実装を進めている。会話の中で決めたことはコードや PR に残りにくく、時間がたつと「なぜこうなっているか」が分からなくなる。AI にとっても、判断の経緯がファイルにあれば同じ議論を繰り返さずに済む。

## 決定

設計上の判断は `docs/adr/` に ADR として残す。書き方は `docs/adr/README.md` に従う。

## 理由

- 判断と理由がコードの近くにあれば、人も AI も参照できる
- 「選ばなかった案」を残すことで、同じ検討をやり直さずに済む

## 検討した他の案

- PR の説明だけに書く: 後から探しにくい。複数の PR にまたがる判断を書きにくい
- issue に書く: 議論の場としてはよいが、結論がまとまった形で残らない

## 影響

- 判断を伴う PR では、ADR の追加・更新が必要か確認する（`quality-gate` スキルのチェック項目）
