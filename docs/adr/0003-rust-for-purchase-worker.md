# 0003. 購入ワーカーだけを Rust で書く

- ステータス: 採用
- 日付: 2026-10-08
- 関連: #4

## 背景

販売開始の瞬間に購入処理を速く実行したい。一方で、予約の登録画面やダッシュボードは速さを必要としない。

## 決定

販売開始時刻に購入を実行するワーカー（striker）だけを Rust（tokio + reqwest）で書く。画面と API は TypeScript で書く。

## 理由

- 速さを決めるのは主にネットワーク（往復回数・TLS の確立・時刻合わせ）で、言語の処理速度の差は数 µs〜数 ms にとどまる。それでも、待機中のタイマー精度や接続の管理を細かく制御しやすい Rust は向いている
- 画面と API は開発の速さを優先し、エコシステムの厚い TS にする
- 本人が Rust を使ってみたいという動機もある

## 検討した他の案

- すべて TS（Node.js）: 1 言語で済むが、タイマー精度と接続管理の制御で Rust に劣る
- Go: 十分速く書きやすいが、Rust を使いたいという希望を優先した

## 影響

- ワーカーと API の間は DB だけでつながる（[0004](0004-shared-sqlite-without-queue.md)）
- 速さの改善は、まず `timings` の計測値を見てネットワーク側から行う
