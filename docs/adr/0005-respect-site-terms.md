# 0005. 利用規約で自動化を禁止するサイトは購入補助のみにする

- ステータス: 採用
- 日付: 2026-10-09
- 関連: #3, #5, #9, #11〜#14

## 背景

最初の対象として TicketDive（コンビニ払い）での自動購入を考えていた。利用規約を確認したところ、次のことが分かった。

- TicketDive（購入者利用規約 第10条）: 自動入力ソフトや BOT による利用、リバースエンジニアリングや構造の解析を禁止。違反時はチケット無効化・払い戻しなし（第11条）
- LivePocket（利用規約 第13条第25号）: ボットなどの自動化手段による利用を禁止。違反時は同様の措置（第14条）

規約違反はアカウント停止やチケット無効化のリスクがあり、先着販売で他のファンと公平に競う仕組みを崩す。

## 決定

- 規約で自動購入や BOT を禁止しているサイトには、自動購入のアダプタを作らない。内部 API の解析もしない
- そのサイトでは購入補助（カウントダウン・リマインド・チェックリスト・手動購入の記録）だけを提供する
- サイトごとの判断は `docs/sites/README.md` に根拠の条文つきで記録し、`packages/shared/src/sites.ts` の `automation` と一致させる
- `automation: "manual"` のサイトでは、Web のフォームと API の両方で `mode: "auto"` を拒否する。ワーカーも、アダプタが登録されていないサイトは処理しない
- 新しいサイトは `.claude/skills/new-site-adapter` の手順で、最初に規約を確認する
- CAPTCHA・待機列・購入枚数の上限は、自動化が許されたサイトでも回避しない

## 理由

- 規約違反のツールは、使わなくても作った時点でリスクになる
- 購入補助だけでも「当日の手間とミス」「振り返り」には十分効く

## 検討した他の案

- 作るだけ作って使わない: 動くものを作るには規約違反の解析と実購入が必要になるため採らない

## 影響

- MVP は「手動購入の補助と記録」になった。ワーカーは、自動化が許されたサイトが見つかるまでモックサイトで検証する
- 規約は改定されるので、対応サイトは確認日と改定日を記録しておく
