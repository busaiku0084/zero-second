# 0007. 時刻は UNIX ミリ秒で保存し、日本時間で表示する

- ステータス: 採用
- 日付: 2026-10-08

## 背景

販売開始からの所要時間をミリ秒単位で比べたい。TS と Rust の両方から同じ値を扱う。日本のチケットサイトが対象。

## 決定

- DB・API・ワーカーの時刻は、すべて UNIX ミリ秒の整数（列名・プロパティ名の末尾を `_at_ms` / `AtMs` にする）
- 時間の長さもミリ秒（`_ms` / `Ms`）
- 画面での表示とフォーム入力は日本時間（Asia/Tokyo）。変換は `apps/web/src/lib/format.ts` に集める
- 所要時間は `+00:42.318` のようなラップタイム形式で表示する

## 理由

- タイムゾーンや形式の解釈違いが起きない
- 言語をまたいでそのまま比較・計算できる

## 検討した他の案

- ISO 8601 文字列: 読みやすいが、比較や差分の計算で変換が要る
- SQLite の DATETIME: 実体は文字列で、ミリ秒の扱いが曖昧

## 影響

- DB を直接読むときは変換が必要（`datetime(x / 1000, 'unixepoch', '+9 hours')`）
