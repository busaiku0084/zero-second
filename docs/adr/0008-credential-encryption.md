# 0008. ログイン情報を AES-256-GCM で暗号化して保存する

- ステータス: 採用
- 日付: 2026-10-09
- 関連: #6

## 背景

自動購入に対応したサイトでは、ワーカーがログインするためにパスワードを保持する必要がある。DB ファイルが漏れても、パスワードがそのまま読めないようにしたい。

## 決定

- パスワードは AES-256-GCM で暗号化して `accounts.encrypted_credentials` に保存する（形式は `iv(12) | tag(16) | ciphertext`）
- 鍵は環境変数 `CREDENTIALS_ENCRYPTION_KEY`（32 バイトを base64）。DB と同じ場所に置かない
- API はパスワードを返さない。Web でも一度登録したら表示しない
- 復号するのはワーカーだけ（ログインの直前）

## 理由

- 認証付き暗号なので、改ざんも検出できる
- 標準ライブラリ（Node の `crypto`、Rust の RustCrypto）で扱える

## 検討した他の案

- OS のキーチェーン: マシンに依存し、ワーカーを別の場所で動かしにくい
- 平文: 採らない

## 影響

- 鍵をなくすと、登録済みのパスワードは復号できない（登録し直す）
- 鍵を変えるときは、全アカウントの再暗号化が必要（手順は `docs/operations.md`）
- ワーカーは RustCrypto の `aes-gcm` クレートで復号する（`crates/striker/src/crypto.rs`）。API で暗号化した値を復号できることをテストで確かめている。復号には API と同じ `CREDENTIALS_ENCRYPTION_KEY` を使う
