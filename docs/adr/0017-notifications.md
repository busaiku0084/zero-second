# 0017. 通知は API のプロセスで作り、アプリ内・Web Push・Webhook で届ける

- ステータス: 採用
- 日付: 2026-10-10
- 関連: #11、[ADR 0004](0004-shared-sqlite-without-queue.md)、[ADR 0008](0008-credential-encryption.md)、[ADR 0016](0016-login-and-per-user-data.md)

## 背景

買い逃しを防ぐため、販売開始の前に知らせたい。自動購入が CAPTCHA などで止まったとき（`needs_human`）や、結果が出たときもすぐ知りたい。
チケットサイトには自動でアクセスしない（ADR 0005）。通知はこのアプリの中の情報だけで作る。

## 決定

- **通知を作るのは API のプロセスの中の `Notifier`**（`apps/api/src/notify/`）。5 秒おきに DB を見て、次の 2 つから `notifications` の行を作り、すぐ届ける
  - リマインド: `reservations.reminder_minutes`（例: `[30, 5]`）で決めた「販売開始の N 分前」を過ぎた、待機中の予約。期限の来たもののうち、いちばん販売開始に近いものを 1 通だけ作る
  - 自動購入の結果: ワーカーが書いた `runs`（`mode = 'auto'`）のうち、`notified_at_ms` が空のもの。成功・失敗・要対応で文面を変える。手動の記録は本人が入力したので知らせない
- 同じ通知を二度作らないよう、`(user_id, dedupe_key)` を一意にする。リマインドのキーには販売開始時刻を入れ、時刻を変えたらもう一度知らせる
- **届け方は 3 つ**
  1. アプリ内: ヘッダーのベルに未読数、`/notifications` に一覧。`notifications` は送信履歴を兼ね、経路ごとの結果（`sent` / `failed` / `skipped`）を残す
  2. Web Push: ブラウザのプッシュ通知。VAPID の鍵は `.env`（`make setup` / `make web-push-keys` で生成）。鍵がなければ使わない。購読の送り先は主なブラウザのプッシュサービス（FCM・Mozilla・Apple・Windows）のホストだけを受け付ける。404 / 410 が返った購読は消す
  3. Webhook: Discord・Slack の受信用 Webhook だけ（URL の先頭で判定）。URL は秘密の値なので、ログイン情報と同じ鍵で暗号化して保存し、API からは返さない。リダイレクトはたどらない
- ワーカー（striker）は通知を送らない。結果を `runs` に書くだけにし、通知は API に任せる

## 理由

- API は常に動いていて DB とユーザーの情報を持っている。ワーカーを止めていても（手動購入だけの人でも）リマインドが届く
- ワーカーは購入の速さに集中させる。外部への通知の送信を購入の処理に混ぜない
- DB をキューの代わりにする方針（ADR 0004）と同じで、新しいミドルウェアが要らない
- アプリ内の通知は設定なしで使え、Web Push と Webhook はスマホにも届く。Discord / Slack はブラウザを閉じていても届き、設定も簡単
- 送り先を決まったサービスに限ると、API から任意の URL（社内のサービスなど）へリクエストを送らせる使い方を防げる

## 検討した他の案

- ワーカーから通知する: リマインドは購入と関係なく、手動購入の予約にも要る。ワーカーが止まっていると届かない
- メール: SMTP などのメール送信の設定が要る
- 任意の Webhook URL: 社内のサービスなどに API からリクエストを送れてしまう
- ブラウザを開いているときだけの通知（Notification API のみ）: 開いていないと届かず、リマインドの目的に合わない

## 影響

- API を複数台で動かすと、同じ通知を同時に作ろうとする。一意制約で重複は防げるが、送信が重なる可能性がある。複数台にするときは Notifier を 1 台だけで動かす
- `make setup` 前に作った `.env` には VAPID の鍵がない。`make web-push-keys` で足す
- VAPID の鍵を変えると、登録済みの端末には届かなくなる（設定画面でもう一度オンにする）
- Web Push はブラウザ（Google・Mozilla・Apple など）のプッシュサービスを経由する。本文には公演名と時刻が入る
