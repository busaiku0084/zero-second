# 0020. パスワードの再設定は管理者が発行するリンクで行い、ユーザーは削除せず停止する

- ステータス: 採用
- 日付: 2026-10-10
- 関連: #31、[ADR 0016](0016-login-and-per-user-data.md)

## 背景

招待制のログイン（ADR 0016）で、パスワードを忘れたときの手段と、使わなくなったユーザーを止める手段がなかった。メールを送る仕組みはない。

## 決定

- **パスワードの再設定は、管理者が発行するリンク**で行う（`POST /users/:id/password-reset`）。24 時間・1 回限り。トークンはハッシュだけを保存し、発行したときに 1 回だけ表示する。同じユーザーに新しいリンクを出すと、前の未使用のリンクは無効にする
- 再設定すると、そのユーザーのセッションをすべて消し、新しいセッションでログインした状態にする
- 再設定の画面と API（`/reset/:token`・`/auth/password-resets/:token`）は公開のルートに加える（トークンを知っている人だけが使える）
- 管理者が 1 人しかいなくてパスワードを忘れたときは、サーバーで `tsx src/cli.ts reset-link <ログイン ID>` を実行してリンクを出す（DB とサーバーに触れる人だけができる）
- **ユーザーは削除せず停止する**（`users.disabled_at_ms`）。停止中はログインできず、セッションと未使用の再設定リンクは消す。自動購入（ワーカー）とリマインドの対象からも外す。データは残し、再開すれば元どおり使える
- 管理者はほかのユーザーの権限（管理者・メンバー）を変えられる。**自分自身は停止も権限の変更もできない**（管理者がいなくなるのを防ぐ）

## 理由

- メール送信の仕組みなしで、安全に再設定できる。リンクは本人に直接渡す前提（招待と同じ）
- 削除すると予約・結果・計測値の扱い（一緒に消すか残すか）を決める必要があり、取り消せない。停止なら取り消せる
- 自分自身を変えられなければ、少なくとも操作している管理者は残る

## 検討した他の案

- メールでの再設定: SMTP などが要る
- 管理者が一時パスワードを決めて伝える: 管理者がパスワードを知ってしまう
- ユーザーの削除: 取り消せず、データの扱いが複雑になる。必要になったら別に決める

## 影響

- 管理者は再設定リンクを相手に安全な経路で渡す必要がある
- 停止中のユーザーの予約は残るが動かない。再開した時点で販売開始前なら、また動く
