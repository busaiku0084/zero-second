# 0023. 公演 URL からの自動入力は、自動化を許可しているサイトだけにする

- ステータス: 採用
- 日付: 2026-10-10
- 関連: #43、[ADR 0005](0005-respect-site-terms.md)、[ADR 0022](0022-switchable-drivers-per-adapter.md)

## 背景

予約の登録で、公演名・席種・枚数を毎回手で入れるのは手間で、席種の名前を間違えると自動購入が準備の段階で失敗する（ADR 0022）。
公演ページの URL を入れたら、これらが自動で入るようにしたい。

公演情報を読むには、サイトのページか API をプログラムで取りに行く必要がある。
TicketDive の購入者利用規約 第10条は BOT などの技術的手段による利用と構造の解析を、LivePocket の利用規約 第13条第25号はボットなどの自動化手段による利用を禁止している（docs/sites/README.md）。
購入でなくても、ページをプログラムで取得して解析することはこれに当たりうる。

## 決定

- 自動入力は **自動化を許可しているサイト（`automation: "auto"`）だけ** にする（`supportsEventInfo`）。それ以外のサイトは API が 422 を返し、ページを取りに行かない。画面では今までどおり手で入れる
- API に `GET /event-info?site=&url=`（ログイン必須）を足す。web は Server Action から呼ぶ
  - モックサイト: 設定の `MOCK_SITE_URL`（ループバックか Docker のサービス名に限る）の公演情報の API を読む。予約の URL からはシナリオだけを読み、そのホストへは送らない。3 秒で打ち切り、リダイレクトに従わない
  - Sauce Demo: 共通の商品一覧から作る（通信しない）。1 点ずつしか買えないので上限は 1
- 予約の登録画面: 公演 URL を入れて 0.4 秒たったら読み、公演名（読み取り専用）・席種（選択肢）・枚数（上限までの選択肢）を入れる。読めなければ理由を出し、前の公演名を消す

## 理由

- 自動購入の予約で使う席種・枚数の上限を、サイトが返す値から選ばせれば、入力の間違いで販売開始の瞬間に失敗することがなくなる
- 「購入でなければよい」とすると、規約の線（ADR 0005）があいまいになる。自動購入と同じ線で区切れば判断がぶれない

## 検討した他の案

- TicketDive・LivePocket も、公開ページの OGP（タイトル）だけ読む: 1 回の取得でも、BOT などの手段による利用・構造の解析に当たりうる。規約の運営者の許可が取れたら見直す
- ブラウザ（利用者の端末）で読む: 他のサイトのページはブラウザの CORS で読めず、結局サーバーから取りに行くことになる

## 影響

- TicketDive・LivePocket の予約は、今までどおり公演名・席種を手で入れる（右側に公演ページを表示して、見ながら入れられるようにした。[ADR 0024](0024-event-page-side-preview.md)）
- 新しく `automation: "auto"` のサイトを足すときは、`apps/api/src/lib/event-info.ts` に読み方を足す（docs/development/adding-a-site.md）
