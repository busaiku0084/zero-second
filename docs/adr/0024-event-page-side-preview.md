# 0024. 自動入力できないサイトは、予約の登録画面の右側に公演ページを表示する

- ステータス: 採用
- 日付: 2026-10-10
- 関連: #46、[ADR 0005](0005-respect-site-terms.md)、[ADR 0023](0023-event-info-autofill.md)

## 背景

TicketDive・LivePocket は、公演 URL からの自動入力の対象外にした（ADR 0023）。
公演名・席種・枚数の上限は手で入れるが、そのたびに別のタブで公演ページを開いて見比べるのが手間で、席種の名前の写し間違いも起きやすい。

## 決定

- 予約の登録画面で、公演 URL を入れたら（0.4 秒待ってから）、フォームの右側に公演ページを iframe で表示する。すべてのサイトで同じ
  - 読み込むのは利用者のブラウザだけ。サーバーはサイトにアクセスせず、ページの中身も読まない（別のオリジンのページは、ブラウザの仕組みでも読めない）
  - 表示するのは、選んだサイトのホストの http(s) の URL だけ。このアプリ自身のオリジンは表示しない
  - `sandbox` に `allow-top-navigation` を入れず、埋め込んだページからこのアプリを遷移させない。リファラーは送らない
- 「別ウィンドウで開く」を付ける。画面の右半分の大きさのウィンドウで開く。サイトが埋め込みを拒否していて表示されないとき、狭い画面（980px 以下）で並べられないときに使う
- 右側の表示は「閉じる」で消し、「右側に表示」で戻せる

## 理由

- 人がブラウザでページを見るのと同じで、BOT などの技術的手段による利用・構造の解析（TicketDive 第10条・LivePocket 第13条第25号）に当たらない
- タブを切り替えずに、見ながら入れられる

## 検討した他の案

- サーバーがページを取りに行き、公演名・席種を読む: 規約に当たりうる（ADR 0023）
- 公演ページの文字を貼り付けて読む: 手間が増え、ページの書き方が変わると読めなくなる。見ながら入れれば足りる

## 影響

- サイトが `X-Frame-Options` や CSP の `frame-ancestors` で埋め込みを拒否していると、右側は空白になる。そのときは別ウィンドウで開く

## 追記（#48）

TicketDive は埋め込みを拒否していた。拒否はサイトが自分を守るための設定なので、回避しない（サーバーで取り直して設定を消すのは、ADR 0023 で避けたサーバーからの取得そのものになる）。

- サイト一覧（`sites.json`）に `embeddable`（既定 true）を足し、拒否すると分かったサイトは false にする。今は TicketDive だけ
- `embeddable: false` のサイトは右側に表示せず、公演 URL の下に「公演ページを右に並べて開く」と、Chrome のタブの分割表示の案内を出す
- 第三者の Cookie の扱いによっては、右側のページではサイトにログインしていない状態になる。購入はこれまでどおりサイトのタブで行う
